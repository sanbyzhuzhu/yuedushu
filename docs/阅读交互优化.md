# 阅读交互与笔记优化

## 使用变化

- 0.3.10：手机长按文字出现两个朱砂圆点，拖动圆点决定选区起点和终点。电脑先鼠标选字，再拖动同样的手柄调整。选区保存完整文字，没有前选/后选 80 字按钮。
- 横排选到本页正文最后一行后，再向下拖过该行才翻一页；竖排要到最后一列末尾，再继续向下或向左拖。双页需要读完第二栏。侧边停留、末行停住、翻页后按住或轻微抖动都不会继续翻页。翻页后选区暂止于新页开头，回到正文继续选字后，才可再次走到页末翻下一页。
- 应用接管选区手柄，同时更新页面和 Range 端点，避免只移动画面、选区却停在上一页。选字期间整章 DOM 保持稳定。单条笔记仍归属一个章节，跨章请分别记录。
- 支持单字划线，长引文不再截断到 2000 字。重复文字用跨节点上下文定位，撤销只处理实际选中范围内的划线。
- 保存划线、编辑批注不再重建整章、重算页码。点笔记列表可定位到划线原文；同章目录和滚动书签也能正常定位。
- 笔记编辑器支持完整引文预览、字数、Ctrl / ⌘ + Enter 保存及当前草稿分享。编辑期间方向键不会翻页；保存失败时保留草稿。
- 笔记存储按操作顺序提交，并等待 IndexedDB 事务完成，避免快速连续操作互相覆盖或提前显示保存成功。
- 划线工具和笔记编辑器跟随阅读主题；调整触控按钮、手机面板、书架留白和无搜索结果提示。

## 验证

```sh
npm run typecheck
npm run build
npm run test:reader
npm run test:touch
```

浏览器回归默认使用本机 Edge，以临时独立浏览器数据运行，自动启动并关闭 `127.0.0.1:5188` 开发服务。不会操作用户的真实书库。

阅读回归可通过 `PW_CHANNEL=chrome` 使用 Chrome，或设置 `READER_URL` 连接已启动的开发服务。63 项检查涵盖真实鼠标拖选、横排/竖排/双页手柄跨页、保存文字与独立测量的起止点逐字一致、分页位置、长引文、重复文本、保存失败、并发写入、简繁转换和重载恢复。触摸脚本在独立的 5190 端口，通过 Chromium 输入协议执行长按、跨两页拖动、反向缩选、松手与取消，36 项检查通过。跨页交互检查不使用注入选区来代替拖动。截图位于 `output/playwright/`，不纳入版本控制。

未连接 Android 真机。不同厂商 WebView、系统手势和软键盘仍需安装 0.3.10 实机验收；浏览器触摸输入不能替代这部分验证。书架标题下的 v0.3.10 用于确认升级生效。

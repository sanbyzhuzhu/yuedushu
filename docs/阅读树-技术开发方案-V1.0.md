## 1. 项目定位与设计理念

**一句话定位**：一款本地优先、支持坚果云同步的极简古典风电子书阅读器，以"树形书架"管理藏书，深度支持中文竖排/横排阅读、简繁转换与划线笔记。

**四个设计关键词**：

1. **极简** —— 界面无广告、无书城、无社交，聚焦"读"本身；默认隐藏一切可隐藏元素。
2. **古典** —— 宣纸质感、水墨视觉、宋体/楷体排印，竖排模式可选"古籍版式"装饰（乌丝栏边框、版心鱼尾、页码）。
3. **美化** —— 精心调校的字体、行距、边距、翻页动效；主题系统（宣纸/羊皮/青灯/墨玉）。
4. **易用** —— 三步内完成导入开读；所有设置即改即见；树形书架支持列表/网格兜底，不做反直觉交互。

**明确不做**（Non-Goals）：在线书源抓取（合规风险大、维护成本高）、社交/社区、DRM 书籍破解（Kindle 带 DRM 的 MOBI/AZW3 不支持）、听书（放 V1.x 后再评估）。

## 2. 调研结论摘要

### 2.1 竞品 / 开源项目对比

| 项目 | 平台 | 格式 | 竖排 | 简繁 | 笔记 | 同步 | 许可证 | 可借鉴点 |
|---|---|---|---|---|---|---|---|---|
| legado（开源阅读） | Android | TXT/EPUB/MOBI/AZW3 | ✗ | ✓ | ✓ | WebDAV 备份 | GPL-3.0 | 产品形态参考；**代码不可复制（GPL）** |
| KOReader | 全平台 | 极广 | 部分 | 部分 | ✓ | ✓ | AGPL-3.0 | 排版引擎思路；代码不可用 |
| Foliate | Linux/GTK | EPUB/MOBI/AZW3/FB2 | ✓ | ✗ | ✓ | 无（本地 JSON） | GPL-3.0（**foliate-js 内核为 MIT**） | **阅读内核直接复用 foliate-js** |
| Readest | Android/桌面/Web | EPUB/MOBI/PDF/TXT/MD | ✓ | ✗ | ✓ | 账号云同步 | AGPL-3.0 | 架构路线验证：foliate-js fork + Tauri 双端 |
| iRead 爱读书 | Win/Android | EBK2/TXT/EPUB/PDF/MOBI/UMD/UPDB | ✓ | ✓ | ✓ | 账号同步 | 闭源 | UPDB 格式来源；竖排古典体验标杆 |
| 静读天下 / Moon+Reader | Android | 极广 | ✓ | ✓ | ✓ | WebDAV/云 | 闭源 | 交互细节与设置项参考 |

**关键结论**：
- **竖排是决定性技术约束**：Android 原生 TextView 与 Flutter 均无成熟的竖排（writing-mode）支持；**只有 HTML/CSS（`writing-mode: vertical-rl`）是成熟方案**。→ 阅读内核必须基于 WebView/Web 技术栈。
- **foliate-js（MIT）是最佳内核底座**：纯 JS、无框架依赖，自带 EPUB/MOBI/AZW3/FB2/CBZ 解析、CSS 多栏分页器（支持竖排）、EPUB CFI 定位、划线 overlayer。Readest 已验证该路线可覆盖移动+桌面。
- **坚果云 WebDAV 是国内最可靠的网盘同步底座**：官方支持应用密码，免费额度够同步进度与笔记。

### 2.2 关键技术事实（已核实）

- **坚果云 WebDAV**：服务器 `https://dav.jianguoyun.com/dav/`，认证为 HTTP Basic（邮箱 + **应用密码**，非登录密码）；免费版流量 **上传 1GB/月、下载 3GB/月**；频率限制 **每 30 分钟 ≤1200 次请求**；单文件上传上限 500MB。
- **Tauri 2.0**：2024-10 发布稳定版，2026 年中已迭代至 2.11.x；桌面端生产级成熟（Spacedrive、AppFlowy、1Password 部分模块在用）；移动端（Android/iOS）可用，主要毛边在插件生态、SAF 文件权限、老设备 WebView 版本碎片化。
- **竖排 CSS 要点**：`writing-mode: vertical-rl` + `text-orientation: mixed`（汉字直立、西文数字旋转、标点自动直排形态）；数字年份用 `text-combine-upright` 直立合并；容器需显式尺寸；用 `@supports` 做渐进增强。

## 3. 功能需求清单

### 3.1 电子书格式支持矩阵

| 格式 | 优先级 | 解析方案 | 备注 |
|---|---|---|---|
| EPUB 2/3 | P0 | foliate-js（MIT） | 重排版为主，兼容固定版式（FXL） |
| TXT | P0 | 自研：编码检测 + 章节正则 + 分块加载 | 支持 UTF-8/GBK/GB18030/Big5；`第X章/卷/回` 等章节识别；目标 50MB 流畅 |
| **MD（Markdown）** | P0 | **markdown-it + DOMPurify → HTML → 与 EPUB 同管线** | 见 3.2 专项说明 |
| MOBI / AZW3 | P1 | foliate-js 内置 mobi 解析器 | 仅无 DRM；KF8（AZW3）完整支持 |
| PDF | P1 | pdf.js（Apache-2.0） | 横排浏览型；划线按"页码+区域"存储；大文件分页懒加载 |
| DOCX（Word） | P1 | mammoth.js（BSD-2）→ HTML | 保留标题/段落/图片结构，统一样式；.doc 老格式不支持（提示转换） |
| UPDB | P2 | 逆向解析（iRead 私有格式，无公开规范） | 尽力而为：支持能解析的版本，失败给出明确提示；仅面向用户自有书籍 |

### 3.2 Markdown 格式专项说明（新增需求）

Markdown 是"作者的格式"，阅读器要把它变成"读者的书"：

- **解析管线**：`markdown-it`（GFM 表格、脚注、删除线）→ `DOMPurify` 净化（防 XSS，本地文件也可能含恶意 HTML）→ 生成 HTML 文档 → 进入统一的古典主题渲染管线。
- **章节切分**：以 `# H1`（无 H1 时退化到 H2）作为章节边界，生成目录；无标题文档视为单章。
- **Front Matter**：支持 YAML 头（`title` / `author` / `cover`），自动填充书籍元数据。
- **图片资源**：支持相对路径引用；导入时把 `md + assets/` 目录打包为内部容器（zip），保证书籍自包含、可同步。
- **样式原则**：忽略原文的颜色/字体样式，**结构保留、视觉统一**——标题、引用、代码块、表格全部套用古典主题（这是阅读器与编辑器的本质区别）。
- **代码块**：等宽字体 + 纸色底框；语法高亮（highlight.js）按需加载，作为可选项。
- **导出联动**：划线/笔记可导出为 MD（见 5.4），形成"MD 进、MD 出"闭环。

### 3.3 功能优先级总表

| 模块 | P0（最小可用产品） | P1 | P2 |
|---|---|---|---|
| 阅读 | TXT/EPUB/**MD** 打开、分页、翻页、进度记忆 | MOBI/PDF/DOCX | UPDB |
| 排版 | 横排；字体字号行距边距；4 主题 | **竖排 + 翻页方向联动**；古籍版式装饰 | 双页对开（平板/横屏） |
| 简繁 | — | OpenCC 全文转换（显示层，原文不变） | 标点/用词风格转换（s2twp 等） |
| 笔记 | 划线（4 色）、书签 | 批注文字、笔记列表跳转 | 导出 MD/文本；生词收集 |
| 书架 | 导入（文件选择器）、网格书架、删除 | **树形分类 + 古树视觉**、搜索排序 | 树视图手势整理、封面美化 |
| 同步 | — | 坚果云 WebDAV：进度/笔记/书架元数据自动同步 | 书籍文件本体同步（L2）、通用 WebDAV 自建 |
| 其他 | 夜间模式、亮度调节 | 阅读统计（时长/进度）、全文搜索 | RSS 订阅、TTS |

## 4. 总体架构

### 4.1 分层架构图

```
┌─────────────────────────────────────────────────────────┐
│                    应用壳层（双端）                        │
│  Android：Tauri 2（系统 WebView）      桌面：Tauri 2      │
│  备选：Kotlin + Compose 原生壳（见 4.3 方案B）             │
├─────────────────────────────────────────────────────────┤
│                统一前端核心（React + TypeScript）          │
│  书架 UI（树形/网格） │ 阅读 UI │ 笔记 UI │ 设置/同步 UI   │
├─────────────────────────────────────────────────────────┤
│                     阅读内核（TS）                        │
│  foliate-js fork：分页器（横/竖排）、CFI、划线 overlayer   │
│  TXT 引擎 │ MD 引擎(markdown-it) │ DOCX(mammoth)          │
│  PDF(pdf.js) │ 简繁 OpenCC │ 主题/字体系统                │
├─────────────────────────────────────────────────────────┤
│              平台适配层（Platform Adapter 接口）           │
│  文件读写 │ SQLite │ 加密存储 │ 前台服务（同步）            │
├─────────────────────────────────────────────────────────┤
│              数据与同步层                                  │
│  SQLite（书架/笔记/进度） │ 文件存储 │ WebDAV 客户端（坚果云）│
└─────────────────────────────────────────────────────────┘
```

**核心原则：阅读内核与壳彻底解耦。** 内核是纯 Web 代码（TS + DOM），不感知平台；壳只负责文件、数据库、网络权限等系统能力，通过统一的 `PlatformAdapter` 接口对接。这保证了方案可切换、桌面端天然复用。

### 4.2 技术选型对比与决策

| 候选 | 竖排支持 | 双端成本 | 生态/风险 | 结论 |
|---|---|---|---|---|
| Flutter | ✗ 竖排需 hack（自绘文本引擎，工作量巨大） | 好 | — | **排除**（竖排一票否决） |
| React Native | ✗ 同上 | 好 | — | **排除** |
| Kotlin 原生 + 自研排版 | 可做但极难（避头尾/标点/混排全手写） | 双份代码 | — | 排除 |
| **Tauri 2 + Web 内核** | ✓ CSS writing-mode 成熟 | **一套壳代码覆盖 Android+桌面** | 桌面生产级；移动端有毛边（可绕过） | **✅ 方案A（推荐）** |
| Android 原生壳 + 桌面 Tauri | ✓（内核相同） | 两套壳，共享前端 | Android 最稳 | 方案B（降级备选） |
| Electron | ✓ | 桌面好、无移动端 | 太重（内存 150MB+） | 排除 |

**决策：方案 A（Tauri 2 全家桶）起步**。理由：
1. 竖排硬需求把技术路线锁定在 Web 渲染，壳层只做系统能力粘合，Tauri 2 桌面成熟、移动端 2 年迭代已可用；
2. 应用是"读文档+轻度网络"型，不依赖 Tauri 移动端薄弱的重原生能力；
3. 包体积小（Android 约 6-10MB），启动快，符合极简理念。

**降级预案**：若 Android 端在文件导入（SAF）、后台同步等处被 Tauri 插件短板卡死，切换方案 B——用 Kotlin + Compose 写原生壳，前端核心 100% 复用，预计损失 2-3 周壳层工作量，内核零损失。

## 5. 核心模块设计

### 5.1 阅读内核与排版引擎

**分页**：基于 foliate-js 的 CSS 多栏分页器（iframe 沙箱渲染）。横排 = 横向栏流；竖排 = `writing-mode: vertical-rl` 下栏自动纵向推进，一屏多列由 `max-column-count` 控制。

**竖排排版规则**（本项目的核心竞争力，需建立专项测试集）：

| 项目 | 规则 |
|---|---|
| 排列 | `writing-mode: vertical-rl`，行自右向左推进 |
| 字符方向 | `text-orientation: mixed`：汉字直立，西文/数字旋转 90° |
| 数字/年份 | 两位数内用 `text-combine-upright: all` 直立合并（如"2026"竖排成一字位） |
| 标点 | 依赖字体的 `vert` 特性自动直排形态（思源宋体/霞鹜文楷均支持）；句读居右上 |
| 避头尾 | CSS `line-break: strict` + `hanging-punctuation`（尽力，Chromium 支持有限需测试兜底） |
| 注音 | `<ruby>` 直排支持（可选功能） |
| 古籍版式（P1） | 可开关的乌丝栏边框、版心鱼尾、页脚"叶 N"页码、朱丝栏批注行 |

**翻页方向与排版联动**（"分清左右"的规则表）：

| 排版模式 | 阅读流 | 点击下一页 | 点击上一页 | 手势下一页 |
|---|---|---|---|---|
| 横排（LTR，简中默认） | 左→右 | 屏幕右区 | 屏幕左区 | 左滑 |
| 竖排 / 繁中（RTL） | 右→左 | **屏幕左区** | 屏幕右区 | **右滑** |

设置项提供"跟随排版（默认）/ 固定横排习惯"两档，避免繁体横排用户困惑。

**主题与字体**：4 预设主题（宣纸 #F7F2E7 / 羊皮 / 青灯夜读 #16181D / 墨玉）+ 自定义（底色/字色/行距/字距/边距/段距全可调）；字体子集化打包（APK 内置霞鹜文楷 Lite 子集约 8-15MB，全量字体首次启动按需下载）。

### 5.2 格式解析层

统一管线：**任意格式 → 归一化为"章节化的 HTML 文档流" → 分页渲染**。EPUB/MOBI/DOCX/MD 原生走此管线；TXT 章节切分后同样走此管线；PDF 例外（固定版式，单独通道）。

- **TXT**：流式读取 + 编码探测（jschardet，优先 BOM，其次置信度）+ 章节正则（`第[一二三四五六七八九十百千0-9]+[章回卷节]`、`Chapter \d+` 等可自定义）+ 章节索引缓存。超大文件（>50MB）分卷懒加载。
- **MD**：见 3.2。
- **EPUB**：foliate-js 直接解析（zip + OPF + XHTML），支持目录、元数据、封面抽取。
- **MOBI/AZW3**：foliate-js 内置解析器，输出 HTML 流。
- **DOCX**：mammoth 语义转换（标题→h1-h6、列表、图片内联），样式丢弃统一换肤。
- **PDF**：pdf.js，页码即章节；文本层支持选择划线；大 PDF 渲染当前页±2 页。
- **UPDB**：iRead 私有格式。策略：魔数识别 → 参考社区零散解析成果逆向（元数据区通常明文、正文压缩/混淆）→ 可解析则导入，否则提示"该 UPDB 版本暂不支持"。**合规声明：仅支持解析用户自有书籍，不提供任何批量解密工具。**

### 5.3 简繁转换（OpenCC）

- **位置**：渲染层转换，**原文件永不修改**，随时切换、即时生效。
- **方案**：opencc-js（词典完整、词组级转换，"皇后"类误转率远低于字符映射）；转换结果按"书 + 配置版本"做 LRU 缓存，翻页级懒转换控制内存。
- **档位**：简→繁（s2t）、繁→简（t2s）、简→台湾正体（s2tw/s2twp）、繁→大陆简体（tw2s）。
- **注意**：转换在分页前对章节 DOM 文本节点执行，CFI 定位基于转换后文档生成，保证划线位置一致；切换转换档位时笔记锚点按原文偏移重映射。

### 5.4 划线、批注与书签

| 书籍类型 | 定位方式 | 划线存储 |
|---|---|---|
| EPUB | EPUB CFI（foliate-js 原生支持） | CFI 区间 + 摘录文本 + 颜色 + 时间 |
| TXT / MD / MOBI / DOCX | 章节号 + 字符偏移 + 前后文 16 字哈希（防偏移漂移自校验） | 同上 |
| PDF | 页码 + 区域四点坐标 | 同上 |

- 划线用 foliate-js 的 overlayer（SVG 覆盖层）渲染，支持直线/波浪线/背景色 4 色；点击划线弹出批注框（竖排模式下批注框横排显示，保证输入体验）。
- **导出**：单书笔记导出为 **Markdown**（书名/作者/时间/原文摘录 `>` 引用/批注），也可导出纯文本；导出文件可再导入本应用阅读——闭环呼应 MD 支持。

### 5.5 树形书架（产品差异点）

**数据模型**：
```
nodes(id, parent_id, name, sort_order, node_type)   -- 树形分类，支持多级
books(id, title, author, format, file_hash, cover_path,
      node_id, last_read_at, progress_pct, created_at)
annotations(id, book_id, type, locator, excerpt, note, color, created_at, updated_at)
progress(book_id, locator, pct, updated_at, device_id)
sync_state(key, etag, local_mtime, remote_mtime, last_sync_at)
```

**三种视图**：
1. **古树视图**（默认，产品灵魂）：SVG 水墨古树——主干 = 全部藏书，一级枝 = 分类，二级枝 = 子分类，书籍 = 叶/果。阅读进度映射"果实成熟度"（未读青果 → 在读半熟 → 读毕红果）；枝条粗细随藏书量变化。实现：预绘制树形骨架 SVG + 书籍封面裁圆挂载 + 平移缩放手势；点击果实进入书内页。
2. **网格书架**：封面 3-4 列网格，按分类分组折叠（兜底，保证效率）。
3. **列表视图**：密集信息列表，按最近阅读/标题/作者排序。

**交互**：长按书籍 → 移动到枝/删除/置顶；拖拽分类节点重挂枝；全局搜索书名/作者/笔记内容。

### 5.6 坚果云同步（WebDAV）

**云端目录结构**：
```
/dav/阅读树/
  ├── manifest.json          # 全局清单（书架树结构 + 各书摘要指纹），~几十KB
  ├── books/<hash>.json      # 每本书：进度 + 笔记 + 书签
  └── files/                 # L2 可选：书籍文件本体
```

**两级同步策略**（应对免费流量 1GB 上行/3GB 下行）：
- **L1 自动同步（默认开）**：manifest + 进度 + 笔记。单文件 <100KB，每次同步总流量 <1MB，月流量几乎可忽略。App 启动 / 阅读中每 3 分钟 / 退出时触发。
- **L2 手动同步（默认关）**：书籍文件本体。逐本上传，明确展示"预计消耗流量"，500MB 以上文件禁止上传（坚果云单文件上限）。

**冲突策略**：
- 进度：取时间戳最新（记录 device_id，UI 显示"已在手机读到 X%"）；
- 笔记：按 annotation id 做并集合并（笔记只增不删的天然 CRDT 特性，删除标记 tombstone）；
- 树结构：整树 JSON 以 last-writer-wins + 操作日志兜底。

**工程约束**：请求队列串行 + 指数退避（尊重 1200 次/30min 限频）；ETag 比对避免无效传输；失败本地排队，恢复网络后续传。同时支持**任意 WebDAV 服务器**（自建/其他网盘），坚果云只是预设模板。

### 5.7 平台适配层（壳层职责）

| 能力 | Android（Tauri 2） | 桌面（Tauri 2） |
|---|---|---|

## 6. UI/UX 设计规范要点

- **色彩体系**：宣纸白 `#F7F2E7`、墨字 `#2A2723`、朱砂批注 `#B03A2E`、黛青辅助 `#34495E`、夜间玄青 `#16181D`；全局无纯黑纯白，保留纸墨温度。
- **字体**：界面与批注用霞鹜文楷（书卷气），正文可选思源宋体/系统字体；字号 16-28pt 连续可调。
- **动效**：翻页两档——"平移"（跟手）与"卷轴"（轻仿真，不做重 3D 仿真）；书架树四季微动效（可选，默认静）。
- **信息架构**：三标签底部导航（书架 / 阅读 = 直达最近在读 / 我的）；阅读页全屏沉浸，点中央呼出菜单（目录/笔记/设置/简繁/同步状态）。
- **空状态**：首启引导"导入第一本书"图示（三步：选文件 → 入架 → 开读）。

## 8. 风险与对策

| # | 风险 | 等级 | 对策 |
|---|---|---|---|
| 1 | Tauri 2 Android 端插件/SAF 毛边 | 中 | 内核解耦已预案；方案 B（Kotlin 壳）随时可切 |
| 2 | 老安卓 WebView 版本碎片化 | 中 | 最低支持 Android 8（WebView 可独立更新）；启动时检测 WebView 版本，`@supports` 特性降级 |
| 3 | 竖排细节多（避头尾/标点/混排） | 中 | 建立竖排测试书单（诗词/小说/学术各 3 本）；分页器留 CSS 补丁位 |
| 4 | UPDB 无公开规范、版本多变 | 高 | 列为 P2 尽力支持；解析失败有明确提示与格式建议；**法务红线：不提供批量解密** |
| 5 | 坚果云限频/流量 | 低 | L1/L2 分层 + 请求队列退避 + 流量可视化 |
| 6 | GPL 污染 | 低 | 依赖清单白名单制（仅 MIT/Apache/BSD/OFL）；legado 等只看产品不抄代码 |
| 7 | PDF 大文件内存压力 | 中 | 页级懒加载、渲染窗口 ±2 页、超 100MB 提示 |

## 附：关键决策速览

1. **技术路线**：Web 阅读内核（竖排唯一成熟解）+ Tauri 2 双端壳；内核与壳解耦，随时可降级 Android 原生壳。
2. **内核底座**：foliate-js（MIT）fork 维护，自带竖排分页、CFI、划线层。
3. **格式策略**：统一归一化为"章节化 HTML 流"再渲染；MD 与 DOCX 走"转 HTML + 统一古典换肤"路线；PDF 独立通道；UPDB 尽力而为。
4. **同步策略**：坚果云 WebDAV 两级同步（元数据自动 / 书籍文件手动），免费流量预算内运行。
5. **产品灵魂**：树形书架（古树视图）+ 古典排版（竖排 + 古籍版式装饰）+ 极简交互。

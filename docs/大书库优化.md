# 0.3.14 大书库优化版

版本号保持 0.3.14。最初的大书库优化包在书架标题旁显示「大书库优化版」；后续「清简书架版」已将版本和构建标记移到「更多 → 关于阅读树」，保留下述容量优化。

## 使用变化

- 网格、列表、树架索引和批量整理每页显示 60 本。支持上一页、下一页和指定页码跳转；搜索、分类和排序仍针对全库，批量整理「全选当前结果」选中所有筛选结果，不只选当前页。
- 返回书架记住本次会话的书架页码。树图适量展示书卷，完整藏书可从分页索引或全库搜索找到。
- 封面单独存放，接近屏幕时读取；书架常驻内存只保留小型书籍信息。旧库首次打开会自动整理封面，并显示加载提示。
- 阅读进度一次批量读取。分类数量一次汇总；千本归类只提交一个事务、刷新一次书架。删除分类只更新受影响的书籍。
- 多文件导入顺序处理，每 20 本更新一次书架，可停止后续导入。已完成的书籍保留。正文、封面、原文件与书籍信息一起保存，写入失败不留下无法阅读的空书。
- 删除书籍同时清理应用内的正文、封面、原文件副本、进度、批注和独立排版数据；不会删除用户原来在文件管理器中的源文件。
- 同步逐本读取封面，处理完即释放，书架状态不保留整库封面。

## 分批备份

打开「备份」后，书籍顺序固定为打开面板时的顺序。选择起始本数与本批数量，默认 100 本、最多 200 本。每批原始数据最多 64 MiB；超出时减少本数，单个超大原文件请另行保存。每次生成一个 ZIP，确认保存后点「准备下一批」，再导出下一批，避免手机浏览器拦截连续下载。

压缩时逐本读取正文，不再把整库正文和原文件一次读入内存。轻量备份完全不读取原文件和字体二进制；完整备份按二进制保存 PDF 等原文件和自定义字体，修正旧版直接 JSON 序列化 ArrayBuffer 导致内容丢失的问题。已经由旧版导出成空对象的原文件不能凭空恢复。

分批包恢复采用合并：其他书籍保留，相同书籍 ID 的正文与批注由备份覆盖；分类和字体目录合并。涵盖全库的小型备份仍为整库替换，恢复前显示对应说明。所有数据库仓库在同一个事务内更新，失败回滚，不留下半次恢复。

旧格式备份继续兼容，但恢复包解压数据也需在 64 MiB 内。新备份格式为 3，请使用「大书库优化版」恢复；应用显示版本号没有改变，数据库内部结构升级为 3。首次迁移和完整备份都需预留足够存储空间。

## 验证范围

`node scripts/test-large-library.mjs` 建立独立的 12,000 本旧版测试书库，包含封面、短正文、1,200 条进度及笔记/二进制原文件样本，验证升级、分页、搜索、返回位置、1,000 本归类、批量导入、失败回滚、备份恢复和同步封面。测试使用独立浏览器数据库，不读写用户的真实书库。

本机 Edge 手机尺寸视口多次测试：首次迁移约 23–26 秒，再次打开约 0.5–0.6 秒，精确搜索约 0.09–0.11 秒，移动 1,000 本约 0.24–0.37 秒。时间受缓存、设备和后台负载影响；不是 Android 真机或上万本完整大 PDF 的性能承诺。没有设置书籍数量上限，真实容量仍取决于设备内存、存储空间及单本文件复杂度。

38 项大书库专项检查与原有 254 项功能检查通过，合计 292 项。另执行 TypeScript 类型检查、生产页面操作和交付物内嵌资源核验。

没有新增运行时依赖。安装包体积与图书数据体积分别计算。

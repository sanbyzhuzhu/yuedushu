# 0.4.10 Wi-Fi 传书

## 使用

1. 接收设备打开电脑版或安卓版阅读树，选择“更多 → Wi-Fi 传书 → 开启 Wi-Fi 传书”。默认不会开启网络监听。
2. 两台设备连接同一局域网。发送设备打开浏览器，输入阅读树显示的完整 HTTP 地址（含端口），再输入本次的 8 位配对码。
3. 选择一本或多本电子书，点击“上传并入架”。文件逐本发送，单本需非空且不超过 256 MiB。
4. 等待“已入架”，再回到阅读树查看。上传完成之后仍有解析和保存过程，不以字节传完当作入架成功。
5. 完成后点击“停止接收”或关闭传书页面。监听会停止，未完成的上传需要重传；已经完整收到的书仍会继续入架。

接收期间请保持阅读树在前台，不要锁屏。第一版支持 IPv4；可以使用 Wi-Fi、同一路由器的网线连接，或手机热点。多个地址中请选择与发送设备同网段的地址。访客网络、AP 隔离、VPN 或防火墙可能阻止设备互访；必要时关闭后重新开启以刷新地址。Windows 提示防火墙时，仅需按你的网络情况允许专用网络访问，本程序不会自动修改防火墙规则。

网页版阅读树不能开启接收服务；发送端只需浏览器，无需安装阅读树。传输使用局域网 HTTP，请只在可信网络中使用。此功能不依赖 WebDAV 账号，不上传到网盘。

## 接收和入架

- 文件分块保存到阅读树的专用临时目录，原始文件名不作为磁盘路径。
- 接收完成后进入待入架队列，前端按块读取并调用与本地导入相同的格式解析器。只有本地保存成功后，接收状态才变为“已入架”。
- 损坏文件或不支持的格式会明确失败，不创建空书；已完整接收的文件即使停止监听仍可入架。
- 新书沿用 0.4.9 的即时展示逻辑，不用退出重进；不自动打开新书打断当前阅读。
- 完成处理后移除暂存文件；重新开启时清理不再处理的旧缓存。退出进程时未完成的接收或尚未入架的临时文件不作为持久传书任务恢复，请重新发送并以接收记录为准。

## 接收限制

每次开启更换配对信息。上传和状态接口需要配对令牌；错误配对码限频。服务校验局域网来源、Host 与 Origin，拒绝路径穿越和不支持的扩展名，限制并发及待处理容量。接口只包含上传和本次接收状态，不提供现有书库列表、读取或下载接口。

## 验证与边界

- Rust 实际 TCP/HTTP 测试：配对、鉴权、中文名、分块读取、入架确认、跨站请求拒绝、错误码限频、重新开启后旧令牌失效、超大请求在写盘前拒绝、中途停止关闭监听并清理半文件、完整文件在停止后继续处理。
- 浏览器接收端测试：模拟原生 IPC，实际调用导入器并写入独立测试数据库；覆盖损坏 EPUB、过期状态拒绝、关闭服务及重启后书籍保留。
- 浏览器发送页测试：实际本地 HTTP 上传多个文件，检查中文名和内容、错误配对、最终入架确认及手机宽度。
- 安装包检查：Windows 与安卓两种 ABI 包含同一前端和原生传书页面；安卓沿用原正式签名。

本机 HTTP 测试与 IPC 测试不能替代真实手机、路由器和系统防火墙验收。没有在用户个人云盘或现有书库中写入测试数据，也没有自动开启面向日常使用的传书服务。
